## 🎯 প্রজেক্ট পরিচিতি ও মানবিক মিশন | Overview

একটি রক্তদান প্ল্যাটফর্ম কোনো সাধারণ সামাজিক যোগাযোগ মাধ্যম বা ই-কমার্স সাইট নয়। এটি একটি **জীবন-মরণ জরুরি স্বাস্থ্যসেবা (Life-Critical Healthcare Application)**। একজন সংকটাপন্ন রোগীর স্বজন যখন রক্তের জন্য আবেদন করেন, তখন প্রতিটি সেকেন্ড গুরুত্বপূর্ণ। 

একজন ২০-৩০ বছরের অভিজ্ঞ প্রিন্সিপাল সফটওয়্যার ইঞ্জিনিয়ারিং দৃষ্টিকোণ থেকে এই সিস্টেমের ৪টি অলঙ্ঘনীয় স্তম্ভ:
1. **রোগীর সংবেদনশীল মেডিকেল তথ্যের কঠোর গোপনীয়তা (Patient Privacy & PHI Protection)**
2. **নিরাপত্তা দাবির পরম সততা (Truth in Security Claims)** — বিভ্রান্তিকর দাবি বর্জন
3. **ডেটার শতভাগ বাস্তবতা (Zero Fake Data Guarantee)** — কোনো ডামি ডেটা দিয়ে জীবন ঝুঁকিতে না ফেলা
4. **অবিচল নির্ভরযোগ্যতা (Resilient Availability)** — অফলাইনেও জাতীয় হেল্পলাইনের উপস্থিতি

## 🛡️ মেডিকেল ডেটা ও প্রেসক্রিপশন প্রাইভেট স্টোরেজ আর্কিটেকচার | Medical Privacy

রোগীর প্রেসক্রিপশন ও মেডিকেল স্লিপ অত্যন্ত সংবেদনশীল পার্সোনাল হেলথ ইনফরমেশন (PHI / PII)। কোনো অবস্থাতেই প্রেসক্রিপশন পাবলিক বাকেটে রাখা যাবে না বা অনির্দিষ্টকালের জন্য সংরক্ষণ করা উচিত নয়।

### ১. ডিপ ফাইল যাচাই (Magic Bytes / MIME Sniffing)
শুধু ফাইলের এক্সটেনশন (`.jpg`) বা ব্রাউজারের পাঠানো `file.type` হেডার নিরাপদ নয়, কারণ যেকোনো ক্ষতিকারক স্ক্রিপ্ট বা এক্সিকিউটেবলকে এক্সটেনশন পরিবর্তন করে আপলোড করা সম্ভব।
- ফাইলের প্রথম ১৬ বাইট সরাসরি মেমোরিতে পড়ে **ম্যাজিক বাইট সিগনেচার** পরীক্ষা করা হয়:
  - **JPEG**: `0xFF, 0xD8, 0xFF`
  - **PNG**: `0x89, 0x50, 0x4E, 0x47, 0x0D, 0x0A, 0x1A, 0x0A`
  - **WebP**: `0x52, 0x49, 0x46, 0x46` (RIFF) ... `0x57, 0x45, 0x42, 0x50` (WEBP)
  - **PDF**: `0x25, 0x50, 0x44, 0x46` (%PDF)
- সর্বোচ্চ সাইজ সীমা: **৫ মেগাবাইট (5 MB)**। যেকোনো অসঙ্গতি সার্ভার ও ক্লায়েন্ট উভয় স্তরেই প্রত্যাখ্যাত হয়।

### ২. EXIF ও GPS মেটাডেটা স্যানিটাইজেশন
স্মার্টফোনে তোলা ছবিতে রোগীর বাসা বা হাসপাতালের সূক্ষ্ম GPS কোঅর্ডিনেট, ক্যামেরা সিরিয়াল ও ডিভাইসের বিবরণ সংরক্ষিত থাকে।
- আপলোডের পূর্বে ব্রাউজারের আইসোলেটেড **HTML5 Canvas ইঞ্জিন** দিয়ে ছবিটি রি-ড্র করা হয়। এর ফলে ছবির মধ্যকার ১০০% EXIF ট্যাগ, GPS জিপিএস তথ্য ও ট্র্যাকিং মেটাডেটা সম্পূর্ণরূপে মুছে যায়।

### ৩. প্রাইভেট বাকেট ও ১৫ মিনিটের শর্ট-লিভড সাইনড লিঙ্ক (Short-Lived Signed URL)
- Supabase Storage বাকেট `prescriptions` সম্পূর্ণ **Private** (`public: false`)।
- কোনো স্থায়ী পাবলিক URL তৈরি হয় না। শুধুমাত্র অনুমোদিত অনুরোধের জন্য **১৫ মিনিট (৯০০ সেকেন্ড)** মেয়াদের টাইম-লিমিটেড ক্রিপ্টোগ্রাফিক সাইনড লিঙ্ক জেনারেট হয়।

### ৪. ভূমিকা-ভিত্তিক অ্যাক্সেস কন্ট্রোল (RBAC & Storage RLS)
- দেখতে পারবেন **শুধুমাত্র**:
  1. যিনি আবেদন করেছেন (`requester`)
  2. হাসপাতালের অনুমোদিত ভেরিফায়েড মেডিকেল মডারেটর / প্ল্যাটফর্ম অ্যাডমিন
- কোনো সাধারণ ভিজিটর বা অননুমোদিত ইউজার প্রেসক্রিপশন অ্যাক্সেস করতে পারবে না।

### ৫. অটো-ডিলিট ও রিটেনশন পলিসি (Auto-Deletion Lifecycle)
- রক্তের অনুরোধ সমাপ্ত (`fulfilled`), বাতিল (`cancelled`) বা মেয়াদোত্তীর্ণ (`expired`) হওয়ার **৩০ দিন** পর ডেটাবেজ ট্রিগার বা `pg_cron` ব্যাকগ্রাউন্ড শিডিউলারের মাধ্যমে প্রেসক্রিপশন ইমেজ স্থায়ীভাবে মুছে ফেলা হয়।

#### 📜 Supabase Storage SQL কনফিগারেশন:
```sql
-- ১. প্রাইভেট বাকেট তৈরি
INSERT INTO storage.buckets (id, name, public, file_size_limit, allowed_mime_types)
VALUES (
  'prescriptions',
  'prescriptions',
  false,
  5242880, -- 5 MB
  ARRAY['image/jpeg', 'image/png', 'image/webp', 'application/pdf']
)
ON CONFLICT (id) DO UPDATE SET public = false;

-- ২. শুধুমাত্র আবেদনকারীর আপলোড পারমিশন
CREATE POLICY "prescriptions_requester_upload" ON storage.objects
FOR INSERT WITH CHECK (
  bucket_id = 'prescriptions' AND (
    auth.uid()::text = (storage.foldername(name))[1] OR
    (storage.foldername(name))[1] = 'requester_temp'
  )
);

-- ৩. শুধুমাত্র আবেদনকারী ও ভেরিফায়েড মডারেটরের রিড পারমিশন
CREATE POLICY "prescriptions_authorized_read" ON storage.objects
FOR SELECT USING (
  bucket_id = 'prescriptions' AND (
    auth.uid()::text = (storage.foldername(name))[1] OR
    EXISTS (
      SELECT 1 FROM public.profiles
      WHERE id = auth.uid() AND role IN ('admin', 'moderator')
    )
  )
);

-- ৪. ৩০ দিন পর প্রেসক্রিপশন ফাইল অটো-ক্লিনআপ ফাংশন
CREATE OR REPLACE FUNCTION public.cleanup_expired_prescriptions()
RETURNS void LANGUAGE plpgsql SECURITY DEFINER AS $$
BEGIN
  DELETE FROM storage.objects
  WHERE bucket_id = 'prescriptions'
    AND created_at < NOW() - INTERVAL '30 days'
    AND name IN (
      SELECT prescription_image_url FROM public.emergency_requests
      WHERE status IN ('fulfilled', 'cancelled', 'expired')
        AND updated_at < NOW() - INTERVAL '30 days'
    );
END;
$$;
```

## 🔒 সুরক্ষিত চ্যাট আর্কিটেকচার ও RLS | Secure Chat

### সত্যনিষ্ঠ নিরাপত্তা দাবি (Truth in Security)
পূর্বের "এনক্রিপ্টেড চ্যাট" দাবিটি প্রযুক্তিগতভাবে অতিরঞ্জিত ছিল। প্ল্যাটফর্মটিতে কোনো End-to-End Encryption (E2EE) যেমন Signal প্রটোকল ব্যবহৃত হয় না। রক্তদাতা প্ল্যাটফর্মে মেসেজগুলো ক্লাউড PostgreSQL ডেটাবেজে সংরক্ষিত থাকে এবং ব্রাউজার-টু-সার্ভার কানেকশনে TLS এনক্রিপশনের মাধ্যমে পরিবাহিত হয়।
- সঠিক পরিভাষা: **"সুরক্ষিত ইন-অ্যাপ মেসেজিং (TLS-ইন-ট্রানজিট + ডেটাবেজ RLS ও প্রাইভেট রিয়েল-টাইম চ্যানেল)"**

### ডেটাবেজ ও রিয়েল-টাইম নিরাপত্তা ব্যবস্থা:
1. **Row Level Security (RLS)**: `chat_messages` টেবিলে RLS সক্রিয়। ব্যবহারকারী শুধুমাত্র নিজের পাঠানো (`sender_id = auth.uid()`) অথবা নিজের প্রাপ্ত (`receiver_id = auth.uid()`) মেসেজ দেখতে পারবেন। তৃতীয় কোনো ব্যক্তি অন্যের মেসেজ কোয়েরি করতে পারবে না।
2. **রিয়েল-টাইম চ্যানেল আইসোলেশন**: চ্যাট রিয়েল-টাইম সাবস্ক্রিপশনে `filter: request_id=eq.{id}` এবং ক্লায়েন্ট-সাইড পার্টনার ভ্যালিডেশন নিশ্চিত করে অন্য কোনো ব্রাউজারে মেসেজ পৌঁছানো রোধ করা হয়েছে।

#### 📜 Chat Messages RLS পলিসি:
```sql
ALTER TABLE public.chat_messages ENABLE ROW LEVEL SECURITY;

-- প্রেরক ও প্রাপক ছাড়া আর কেউ মেসেজ পড়তে পারবে না
CREATE POLICY "chat_messages_participant_select" ON public.chat_messages
FOR SELECT USING (
  auth.uid() = sender_id OR auth.uid() = receiver_id
);

-- শুধুমাত্র লগইনকৃত ব্যবহারকারী নিজের নামেই বার্তা পাঠাতে পারবে
CREATE POLICY "chat_messages_sender_insert" ON public.chat_messages
FOR INSERT WITH CHECK (
  auth.uid() = sender_id
);
```

### ভুয়া সিড ডেটা বর্জনের নীতি (Zero Fake Data Guarantee)
একটি জীবন-মরণ অ্যাপে ক্লাউড ডেটাবেজ না পেলে ভুয়া ডোনার বা ভুয়া ফোন নম্বর দেখানো **মারাত্মক বিপজ্জনক**। হাসপাতালের সামনে অপেক্ষারত একজন রোগীর স্বজন ভুয়া নম্বরে কল করে সময় নষ্ট করলে রোগীর জীবন বিপন্ন হতে পারে।
- **প্রোডাকশন মোডে কোনো ডামি বা সিড ডেটা দেখানো হয় না।** কোনো এলাকায় রক্তদাতা নিবন্ধিত না থাকলে অ্যাপটি স্পষ্টভাবে জানাবে: *"বর্তমানে এই এলাকায় কোনো রক্তদাতা নিবন্ধিত নেই।"*
- ডামি সিড ডেটা শুধুমাত্র ডেভেলপমেন্ট এনভায়রনমেন্টে `NEXT_PUBLIC_DEMO_MODE=true` ফ্ল্যাগ থাকলেই টেস্ট করার জন্য চালু হয়।

### টাইমস্ট্যাম্প সহ অফলাইন ক্যাশ ("সর্বশেষ আপডেট: X")
যদি ব্যবহারকারী পূর্বে অ্যাপটি ব্যবহার করে থাকেন এবং হঠাৎ ইন্টারনেট সংযোগ বিচ্ছিন্ন হয়:
1. ডিভাইস লোকালস্টোরেজ থেকে পূর্বে ফেচ করা **প্রকৃত রিয়েল ডেটা** লোড করে।
2. স্ক্রিনের শীর্ষে স্পষ্ট নোটিশ দেখানো হয়:  
   `"⚠️ অফলাইন মোড সক্রিয় — ডিভাইসে পূর্বে সংরক্ষিত ডেটা প্রদর্শিত হচ্ছে (সর্বশেষ আপডেট: ১০ মিনিট আগে)"`
3. রক্তদাতার নামের পাশে স্পষ্ট ক্যাশ বয়স দেখানো হয়।

### অপরিবর্তনীয় জাতীয় জরুরি হেল্পলাইন (Immutable Helplines)
ইন্টারনেট সংযোগ থাকুক বা না থাকুক, প্ল্যাটফর্মের প্রতিটি স্ক্রিন থেকে নিম্নলিখিত জরুরি হটলাইনগুলোতে ১-ট্যাপে সরাসরি কল করার সুবিধা অপরিবর্তনীয়:

## 🏗️ আর্কিটেকচারাল প্যাটার্ন | Architectural Patterns

1. **মেডিকেল গোপনীয়তা ও EXIF পিউরিফিকেশন**:  
   রোগীর ব্যক্তিগত প্রেসক্রিপশন আপলোডের সময় ক্লায়েন্ট-সাইডে Canvas ইঞ্জিন ব্যবহার করে ছবির সমস্ত EXIF ও GPS মেটাডেটা ছেঁটে ফেলা হয়। Supabase-এর প্রাইভেট বাকেটে ১৫ মিনিটের সাইনড লিঙ্কে শুধুমাত্র আবেদনকারী ও ভেরিফায়েড মডারেটরের অ্যাক্সেস নিশ্চিত করা হয়েছে।
2. **জিরো ফেক ডেটা গ্যারান্টি (Zero Fake Data Guarantee)**:  
   জরুরি রক্তদানের মতো জীবন-মরণ অ্যাপে ক্লাউড অনুপস্থিত হলে কাল্পনিক ডোনার বা মনগড়া হাসপাতাল স্টক দেখিয়ে রোগীর স্বজনদের সময় নষ্ট করা রোধ করা হয়েছে। প্রোডাকশনে শুধুমাত্র বাস্তব ক্যাশ করা ডেটা টাইমস্ট্যাম্প সহ প্রদর্শিত হয়।
3. **প্রমাণভিত্তিক সততা (Truthful Security Claims)**:  
   E2E দাবি পরিহার করে পরিষ্কারভাবে "সুরক্ষিত চ্যাট (TLS + RLS)" উল্লেখ করা হয়েছে এবং ডেটাবেজে RLS ও চ্যানেল ফিল্টারিং দিয়ে অন্যদের মেসেজ দেখা সম্পূর্ণ প্রতিরোধ করা হয়েছে।
4. **হাইড্রেশন নিরাপত্তা (`React.useSyncExternalStore`)**:  
   লোকালস্টোরেজ স্টেট ও সার্ভার সাইড রেন্ডারিংয়ের মধ্যে অমিল রোধ করতে `useSyncExternalStore` ব্যবহৃত হয়েছে, যার ফলে কোনো হাইড্রেশন ফ্লিকার হয় না।
5. **অফলাইন-ফার্স্ট রেজিলিয়েন্স ও পিডব্লিউএ (PWA)**:  
   Service Worker এবং টাইমস্ট্যাম্পড ক্যাশের মাধ্যমে অফলাইনেও অ্যাপটি লোড হয় এবং জাতীয় ১৬২৬৩ ও ৯৯৯ হেল্পলাইনের অবিচল সংযোগ নিশ্চিত থাকে।
